# 第二轮工具修复计划（修订版）

## Fix 1: Probe 安装方案讨论（替代当前 scene_root + persistent 方案）

### 当前方案问题

当前代码（已由 glm5.1 修正）将探针挂在 `_get_user_scene_root()` 下：
```gdscript
scene_root.add_child(probe)
probe.owner = scene_root  # persistent=true 时
```

副作用：
1. `persistent=true` → 探针被写入 .tscn 文件 → 导出游戏时包含探针节点
2. `persistent=false` → 探针在场景关闭/重开后丢失

### 候选方案 A: 通过 ProjectSettings 注册 Autoload

```gdscript
# _tool_install_runtime_probe
ProjectSettings.set_setting("autoload/MCPRuntimeProbe",
    "*res://addons/godot_mcp/runtime/mcp_runtime_probe.gd")
ProjectSettings.save()

# _tool_remove_runtime_probe
ProjectSettings.clear("autoload/MCPRuntimeProbe")
ProjectSettings.save()
```

优点：
- 不修改 .tscn，不污染导出
- 探针是 Autoload → 跨场景切换存活
- 所有场景自动包含探针

缺点：
- 每次 `install/remove` 都会写入 `project.godot`
- 需要 `ProjectSettings.save()`（IO 操作）
- 设置项可能在编辑器关闭后残留

适用场景：探针作为长效调试工具使用，不是一次性操作。

### 候选方案 B: 保持 scene_root 添加 + `persistent=false` 默认

```gdscript
var persistent: bool = params.get("persistent", false)  # 默认 false
```

优点：
- 不修改 .tscn（persistent=false）
- 不修改 project.godot
- 探针在当前编辑会话中可用

缺点：
- 探针在场景关闭/重开后丢失（需重新 install）
- 不跨场景存活
- `run_project` 时仍会带上探针（编辑场景的运行时快照自带节点）

### 候选方案 C: `persistent=false` + `editor_interface.mark_scene_as_unsaved()` 跳过

在 persistent=false 时不调用 `mark_scene_as_unsaved()`，完全避免编辑场景被标记为脏。

```gdscript
var persistent: bool = params.get("persistent", false)
if persistent:
    probe.owner = scene_root
    editor_interface.mark_scene_as_unsaved()
```

优点：完全不碰任何文件（.tscn / project.godot）

### 推荐

**候选方案 C**（最简洁、零副作用）。如果用户需要跨场景存活，后期可升为 Autoload 方案。

## Fix 2: Runtime 工具 pending 自动重试（方案B — 工具层轮询）

### 实现方案

不修改 `_request_runtime_probe` 内部逻辑，而是添加独立 helper 函数在工具层做轮询：

```gdscript
# 新增 helper（debug_tools_native.gd）
func _request_runtime_probe_poll(
    command: String, payload: Array, response_messages: Array,
    params: Dictionary, match_fields: Dictionary = {}
) -> Dictionary:
    var result: Dictionary = _request_runtime_probe(command, payload, response_messages, params, match_fields)
    if result.get("status") == "pending":
        var timeout_ms: int = maxi(int(params.get("timeout_ms", 1500)), 100)
        var deadline_ms: int = Time.get_ticks_msec() + timeout_ms
        while Time.get_ticks_msec() < deadline_ms:
            OS.delay_msec(50)
            result = _request_runtime_probe(command, payload, response_messages, params, match_fields)
            if result.get("status") != "pending":
                break
    return result
```

### 受影响工具（首批 5 个核心工具）

| 工具函数 | 当前代码 | 修改方式 |
|---|---|---|
| `_tool_get_runtime_scene_tree` (L1734) | `return _request_runtime_probe(...)` | 改为 `_request_runtime_probe_poll(...)` |
| `_tool_inspect_runtime_node` (L1756) | 同上 | 同上 |
| `_tool_evaluate_runtime_expression` (L1896) | 同上 | 同上 |
| `_tool_get_runtime_screenshot` (L2591) | 同上 | 同上 |
| `_tool_get_runtime_info` (L1624) | 有 stale 回退 + bare call | 改为 poll，去掉 stale 回退 |

`_tool_get_runtime_info` 当前有 pending → stale 回退逻辑，改为 poll 后可直接返回 success，stale 回退不再需要。

剩余工具函数（`_tool_create_runtime_node`、`_tool_simulate_runtime_input_action` 等 20+ 个）可在后续迭代中逐步迁移。

### 与 Fix 3（await_runtime_condition）的关系

await_runtime_condition 内部已有一个轮询循环，每次迭代调用 `_tool_evaluate_runtime_expression`。新 helper 保证此调用不返回 pending，因此循环不会因 pending 而陷入超时死锁。**无需单独修改 await_runtime_condition。**

## Fix 3: execute_script 多行委托返回值

修改 `_tool_execute_script` 中的多行路径（L2984），在代码末尾追加 `_custom_print()` 输出最后一个表达式：

```gdscript
if "\n" in code:
    # Capture the last expression value when delegating to execute_editor_script
    var wrapped: String = "var __mcp_last__ = null\n" + code
    if not wrapped.ends_with(";"):
        wrapped += "\n__mcp_last__ = (" + code.rsplit("\n", true, 1)[1].strip_edges() + ")"
        wrapped += "\n_custom_print(str(__mcp_last__))"
    else:
        wrapped += "\n_custom_print(str(__mcp_last__))"
    params["code"] = wrapped
    return _tool_execute_editor_script(params)
```
